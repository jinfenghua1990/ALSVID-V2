# V2 门户迁移

旧项目的 www、admin、my、dealer 入口在对应功能验收和域名迁移完成前继续保留。V2 不调用旧系统业务接口，也不自动导入旧业务表。

## 产品目录

- 后台「商城 → 官网产品发布」为现有产品填写独立的公开内容。支持中文、英文、德文；未填写的语言不展示该产品。
- 保存草稿不会改变已发布内容；管理员显式发布后，访客才能读取。只读账号不能保存、发布或下架。
- 公开内容仅包括手动填写的名称、型号、说明、参数和明确勾选的产品图片，不自动公开内部产品名称、SKU 价格、成本、BOM、库存、备注、对象存储路径或账号信息。
- 下架或停用产品后，公开目录、详情和图片接口都拒绝访问。响应不缓存；无法撤回访客此前已下载的内容。
- 本机目录入口：`/catalog/zh`、`/catalog/en`、`/catalog/de`。原 `/` 继续为管理后台，尚未切换域名。
- 官网首页入口：`/www`、`/www/zh`、`/www/de`；部署到 `www.*` 主机名时由前端自动显示官网首页。`admin.*` 保持管理后台，`my.*` 和 `dealer.*` 分别进入对应门户。
- 新表 `alsvid_v2.catalog_publications` 只保存 V2 发布草稿与已发布快照，版本冲突返回 409，操作记录在现有审计表中。迁移不默认发布任何现有产品。

## 管理员审核的门户权限

- 本机车主入口 `/my`，经销商入口 `/dealer`。账号由管理员在「设置 → 门户账号与车辆审核」核实身份或合作资格、填写审核记录后创建。不自动注册、升级或导入旧账号。
- 车主与经销商只可使用各自的门户接口。内部产品、生产、财务和账号接口继续拒绝这些角色；只读内部账号也不能查看门户审核资料。
- 门户提交 VIN 与凭证说明仅形成待审核申请，不查询或揭示车辆是否存在。管理员核实并批准后，账号才获得该车辆的基本档案访问权。
- 同一车辆最多一个有效车主授权。新申请不能覆盖现有车主；需核实并明确撤销旧授权后再批准。经销商授权逐账号、逐车辆审批，尚未建立多员工经销商组织权限。
- 获授权账号可提交服务申请。管理员受理时在同一事务中建立现有维修工单，门户只返回该账号自己的申请、公开回复和对应工单状态。重复提交同一申请编号不会重复建立记录；重复受理不会重复建单。
- 撤销车辆授权后，该账号不能再读取该车档案、提交服务申请或查看原服务进度。新车主不能读取旧车主的服务申请。停用账号或改密会使原登录失效。
- 账号创建不发送通知或密码；管理员通过已核实的联系方式交付账号。门户可自行改密，管理员可重置密码。

## 切换域名前仍需完成

- 实际身份、购车或合作凭证核实与管理员验收；当前支持审核记录，尚无凭证附件上传、自动邮件核验或自助密码找回。
- 经销商组织与员工管理、订货等完整业务流程；当前只提供逐账号车辆授权与售后申请。
- 对照现有官网核验导航、经销商查找、资料下载及购物流程；产品目录不等同于完整商城。
- 实际多语言产品内容录入与发布验收。
- 公网 HTTPS、代理来源与登录限流、域名入口及回滚验证。公网配置 PR #14 仍为草稿，不因目录功能完成而自动开放本机服务。
- 四个入口及其业务流程验证通过后再切换，确认 V2 与其他业务不依赖旧资源后删除旧项目。

## 验证

`server/test/catalog.test.js` 和 `server/test/portal.test.js` 仅允许主机为 `127.0.0.1` 或 `localhost`、数据库名以 `alsvid_v2_test_` 开头的临时 PostgreSQL。它创建测试夹具，不得指向正式数据库。GitHub Actions 使用独立的 PostgreSQL 16 服务执行发布、越权、并发冲突、下架与图片访问测试并构建前端。
